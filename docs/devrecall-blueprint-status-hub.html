03 / system

One worker owns the state

UI code sends typed requests. The service worker coordinates capture, storage, LLM work, and retrieval. IndexedDB remains the durable source of truth when Chrome suspends the worker.

inputs

Content + UI

Readability extracts pages. Side panel and Options send typed requests.

→
coordinator

MV3 service worker

Handlers route requests to capture, retrieval, auto-save, settings, and repository services.

→
state + models

Dexie + OpenAI

Pages and chunks stay in IndexedDB. Model calls add metadata and vectors.

What stays local

Saved records, extracted page text, chunks, embeddings, and the API key are persisted in the browser profile. There is no DevRecall sync server.

What crosses the network

With an API key configured, saved text goes to gpt-4o-mini for enrichment. Chunks and semantic search queries go to text-embedding-3-small. "Local-first" does not mean offline.

04 / choices

The decisions worth remembering

These choices explain why the code looks the way it does. They are more useful on a return visit than a file inventory.

Hybrid beats either search alone

BM25 catches exact terms and works without a key. Vector search catches paraphrases. RRF combines ranks without pretending their raw scores are directly comparable.

Auto-save starts off

Saving browsing history without consent was the wrong default. The feature is opt-in, allowlisted, and starts only after 30 seconds on a matching page.

The worker can disappear

Chrome may suspend an MV3 worker after roughly 30 seconds. Dwell state uses chrome.alarms and session storage instead of in-memory timers.

Keep the source text

Full extracted text remains with each page so a future chunking or embedding change can rebuild the search index without recapturing the page.

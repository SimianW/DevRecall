01

你能直接感受到的变化

搜索更容易命中

正文之外，标题、摘要、主题、技术名、域名和 URL 也参与检索。标题与标签有更高权重，结果会显示命中的字段。

支持 C++、C#、camelCase 和中文分词。搜 state 可以找到 useState。

筛选不再漏掉旧收藏

先对整个库筛选，再截取结果。浏览列表可以继续加载，筛选后的列表也一样。保存、删除或导入后，当前搜索会更新。

/ 或 Ctrl / ⌘ K 聚焦搜索，Esc 清空。卡片可展开查看命中依据。

备份终于能恢复

选择 JSON 后先预览数量，再确认导入。恢复保留现有收藏，跳过重复 URL；如果写入失败，整批回滚。文本和标签恢复后可直接本地搜索。

设置 → Data Management → Import backup。导入不会调用 AI。

操作有明确的结果

保存、设置、列表读取都有失败反馈或重试入口。删除前确认，等待中的操作不重复提交。无法保存的浏览器内部页面会给出说明。

同时检查了浅色、深色和 320 像素窄侧栏，修正横向溢出。

02

底层改动，为什么值得做

位置 这次的处理 带来的好处
搜索索引 每个语料版本复用 BM25 索引；正文与元数据共用分词和高亮规则。 重复搜索不必重建词频统计，命中与高亮更一致。
数据写入 备份先校验，页面和文本块事务写入；清空时使旧保存任务失效。 避免导入一半、重复覆盖和清空后旧任务重新写回。
界面与 worker 关键写操作要求明确成功响应；列表和搜索丢弃过期返回值。 不把通信失败显示成成功，不让旧结果覆盖当前状态。
AI 边界 请求及响应读取限时 30 秒；严格检查标签和 1536 维向量；发送前复核授权。 异常响应不会被当作成功。超时等结果不明的 POST 不自动重发，降低重复计费风险。
构建依赖 tokenizer 只加载实际使用的 cl100k_base 字典。 worker 体积约减少 4.51 MB；gzip 后约 2.65 MB → 0.56 MB。

没有更换技术栈或数据库格式。仍是 React、TypeScript、Dexie 和 Chrome MV3；这次优先收紧已有模块的职责与数据边界。

04

验证了什么，还缺什么

代码验证

  • 完整单元与集成测试，含新增搜索、备份和并发回归。
  • TypeScript、ESLint、Prettier 和生产构建。
  • 两轮独立审查，分别检查项目规范和用户需求。
  • 本地保存、AI 回退与授权撤销都有自动化覆盖。

真实浏览器验证

  • 全新 Chromium profile 加载打包后的 MV3 扩展。
  • 65 页导入、旧页面筛选、加载更多、导出去重。
  • 本地 HTTP 网页提取、手动保存和删除后的实时搜索。
  • 浅色、深色、320px 布局、Esc 清空，无未捕获页面异常。
  • 这些 Local-only 流程的 OpenAI 请求数为 0。

这还不是一次正式发布。没有用真实 API key 做付费端到端测试，没有测试 Chrome 商店安装、不同机器上的长期使用或上万页规模。

备份限 25 MiB、5,000 页，不含 API key、设置和向量。恢复后的语义索引需要另行授权重建。已经发出去的 AI 请求无法撤回；撤销授权阻止后续发送，也不会自动重试结果不明的请求。

构建仍有 tokenizer 大块提示及现有的构建插件选项警告，构建本身通过。体积数字来自本地构建，不等于启动速度或搜索延迟的实测提升。
